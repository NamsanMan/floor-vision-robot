# DS-Net을 Pi 5 CPU에 올리기

로봇에 NPU가 없어서, segmentation 모델이 Raspberry Pi 5 CPU에서 얼마나 빨리, 얼마나 덜 망가지면서 돌 수 있는지부터 측정했다. 모델은 내가 연구에서 제안한 DS-Net(CamVid 학습)이다. 논문이 투고 중이라 CamVid 점수는 절댓값 대신 360×480 입력 대비 변화로만 적는다.

## 입력 해상도에 따른 성능

CamVid로 학습한 모델을 재학습 없이 입력 해상도만 줄였을 때의 mIoU 변화와 Pi 5 FP32 지연.

| 입력 | mIoU 변화 | Pi FP32 지연 |
|---|---|---|
| 360×480 | 기준 | 360 ms |
| 300×400 | −2.7 | |
| 270×360 | −6.4 | |
| 240×320 | −7.3 | 148 ms |
| 180×240 | −13.2 | 80 ms |

작고 가는 클래스(보행자, 기둥, 표지판)부터 무너졌다. 재학습 없이 잰 값이라 하락폭은 최대치다.

## INT8 정적 양자화

ONNX Runtime 정적 양자화(QDQ, 활성값 int8, weight 채널별 int8, Conv·MatMul·Gemm만 양자화, 보정 128장). 정확도 손실은 360×480에서 −0.25\~−0.30, 240×320에서 −0.10\~−0.12였고, 모델 크기는 14.3 MB에서 4.2 MB가 됐다. 평가를 위해 따로 만든 열화 15종(저조도 노이즈, 초점 흐림, 모션 블러, JPEG, 저해상도 등)에서도 가장 나쁜 경우가 −0.54라 QAT는 하지 않았다.

출력 점수는 평균 3.4% 흔들리지만 예측이 바뀐 픽셀은 0.92%뿐이었다. 그중 90%가 클래스 경계 2픽셀 안에 있었고, 원래 1등과 2등 점수가 거의 같던 픽셀이었다.

## Pi 5 속도 (ONNX Runtime 1.23.2, 2스레드, ROS 실행 중)

| | 360×480 | 240×320 | 180×240 |
|---|---|---|---|
| FP32 | 360 ms | 148 ms | 80 ms |
| INT8 | 270 ms | 108 ms | 54 ms |
| INT8 + GELU fusion + 마지막 업샘플 제거 | 229 ms | **85.6 ms** | |

양자화하고 나서 프로파일을 다시 보니 병목이 옮겨 가 있었다. FP32에서는 디코더의 특징을 합치는 conv가 가장 컸는데, INT8에서는 GELU(Erf), int8↔float 변환, Transpose처럼 weight와 상관없는 연산이 커졌다. ONNX Runtime은 FP32 그래프의 GELU는 자동으로 묶으면서 QDQ 그래프에서는 놓치는 것을 발견했다. `onnxruntime.transformers`의 FusionGelu로 직접 묶으니 18% 빨라졌고 출력 차이는 0이었다. 마지막 업샘플 제거로는 추론 시간이 1.7%만 줄었다. 4스레드는 평균이 빨라지지는 않았고 튀는 지연만 커져서 2스레드로 정했다.

INT8 240×320에 GELU fusion까지 한 85.6 ms(FP32 대비 1.73배)는 FP32 180×240(80 ms)과 속도가 비슷하면서 mIoU는 5.8 높다. 로봇에는 이 설정을 올렸다.

## 연구실 영상에 그대로 넣어 보기 (fine-tuning 전)

로봇 카메라 영상에서도 보이는 바닥은 대체로 주행 가능 영역으로 잡았다. 하지만 클래스 이름은 엉뚱했고(흰 벽을 하늘로) 물체 밑동을 바닥으로 칠하는 일이 있어서 [fine-tuning](../../training)으로 이어졌다. 깊이 카메라는 바닥에서 10 cm 남짓한 이 높이에서 바닥을 거의 못 재서, 바닥은 segmentation으로 보기로 했다.

## 주의할 것

양자화의 보정(calibration) 단계에서 ONNX Runtime은 모든 보정 이미지의 중간 결과를 한꺼번에 메모리에 올린다(360×480은 장당 273 MB). 두 개를 병렬로 돌렸다가 80 GB까지 차서 멈췄고, 8장씩 나눠 보정하게 고쳤다.

## 파일

`scripts/`: 해상도 스윕(`res_sweep.py`), PTQ 평가(`ptq_eval.py`), 열화 평가(`degr_eval.py`), 그래프 최적화(`opt_graph.py`), Pi 프로파일(`ort_profile.py`), 바뀐 픽셀 분석(`why_small.py`). 논문 학습 코드(비공개)를 불러오기 때문에 그대로는 돌지 않는다(`DSNET_REPO` 환경변수). `results/`: Pi 프로파일 출력.
